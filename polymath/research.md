# 取材

取材先于写课。没有可核对的来源，不准展开教案正文。

## 检索顺序

1. **权威入口**：官方文档、语言/协议规范、标准组织页面、项目 README 里指向的 docs。
2. **结构化教程**：官方 tutorial、大学公开课提纲、被广泛引用的系列文章。优先近 2–3 年仍在维护的材料；经典基础可更早，但要标明「基础仍成立、实现细节可能过时」。
3. **公开仓库**：GitLab 优先检索；结果不足再查 GitHub。选 star/fork 或近期提交能说明仍在用的项目；读 README、目录和 1–2 个核心文件路径，确认能支撑案例，不要只抄星数。
4. **对照与争议**：同一概念若有两派做法，各找一个代表性来源，教案里写成取舍，不假装只有一种真理。

用 WebSearch / WebFetch（或当前环境等价工具）实际打开。打不开就换源，并在来源表注明失败原因。

最少合格集：

- 1 条权威文档或规范
- 1 条高质量教程或学习笔记
- 2 个可打开的公开仓库（GitLab 或 GitHub）

随难度/课型加减：

- **简单**：仓库可减为 1 个（README 级即可）；教程可用官方导言代替长教程
- **前沿实例=开**（或难度=复杂且默认开）：另加 ≥1 条近 1–3 年的论文/RFC/发布说明，以及 ≥1 个可打开的前沿实例入口（仓库路径、demo、或可复现实验说明）；清单里标「前沿，可能过时」

## 筛选

留下：能支撑「概念 → 机制 → 案例」的材料。  
丢掉：纯营销页、无代码的概念漫画当唯一依据、年代久远且与现行 API 冲突又未标明过时、无法访问的链接。

仓库要能指出：哪条路径/模块会在案例里被引用。指不出具体路径的仓库，降为「扩展阅读」，不充当主案例。

## 禁止

- 编造仓库名、star 数、文档章节
- 用「据某知名公司内部实践」且给不出公开链接
- 把搜索摘要里的句子当成已读全文
