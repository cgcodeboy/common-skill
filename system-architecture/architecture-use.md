# 使用

先按 [architecture-install.md](architecture-install.md) 装到个人技能目录，并新开对话。

## 怎样开口

显式调用：

```text
/system-architecture
做仓储入库预约。上午是高峰，同一月台不能被订两次。六个月内可能变成五个仓库，团队只有四个人。先定系统架构。
```

也可以不打斜杠，直接说要做系统架构、架构选型、质量属性、C4、4+1、架构图或架构评审。描述里带这些事，对话会选用本技能。

本对话一旦开始做架构，后面的「改成每个仓库一个服务」不用再打斜杠。

## 会得到什么

产品仓库里的两份文档：

- `docs/框架设计.md`：外部关系、备选方案、逻辑架构和物理架构
- `docs/概要设计说明书.md`：按 GB/T 8567-1988 的概要设计章节，写到模块、模块间接口、运行、数据结构和系统级出错处理

模块内部的算法不在这两份里。那是详细设计说明书。

## 怎样提修改

指出哪条场景或约束变了。例如「一个仓坏了，其他仓还要能预约」会重开部署。只说「改成微服务」时，会先对照现有场景：若现有场景并不要求独立部署，会先给一个不拆服务的改法。你再明确接受被牺牲的那条度量，才会改轴。

## 不负责什么

人如何在界面上完成任务、原型和视觉，用 `/system-interaction`。两个技能可以先后用：先定边界和数据所有权，再定调度台怎么操作。架构交付里不要顺便设计界面。
