# 模式

部署单元、数据所有者和集成风格已经在架构里决定。这里只扫描这个单元内部的变化轴。某一族的结论若迫使你新增服务或新增真相，停止，把矛盾写回架构。

每一族在交付里两行以内：没有这类问题；或者选了谁、放弃了同族的谁、依据哪条场景。

## 分解与规则

| 模式 | 采用 | 放弃 |
| --- | --- | --- |
| 聚合 | 用它划定一次事务里的一致性边界，外部只通过它的行为修改 | 把整个库或整张日历都放进一个聚合再加载 |
| 实体 | 有连续身份，属性变了仍是它 | 没有身份 |
| 值对象 | 替换整个值，没有独立生命周期 | 还要单独持久化并引用它 |
| 领域服务 | 判断跨过多个实体，但不属于其中某一个 | 把它做成什么都能调用的工具类 |
| 规格 | 同一条匹配规则要在确认、查询下一空档两处使用 | 规则只写一次且不会再被引用 |
| 策略 | 同一操作的算法会按数据替换，调用顺序不变 | 只有一个算法，策略接口没有第二个实现 |
| 状态 | 迁移规则多于一两个布尔判断 | 用它包裹一个几乎不迁移的标志位 |
| 工厂 | 创建时的不变量复杂，不能靠调用方填字段 | 创建只是赋值 |
| 仓库 | 按聚合标识取回，领域不写查询语言 | 把报表查询塞进仓库 |
| 工作单元 | 一次命令改多个持久化对象，要一起提交 | 一次只写一行且没有发件箱 |

桥接、组合、装饰、访问者、解释器这些结构或行为模式，只有出现了对应的变化轴才选用：两个维度独立增加才用桥接；结构稳定且操作会增加才用访问者；文法小而稳定才用解释器。没有这条轴，就写「创建族 / 结构族 / 行为族没有这类问题」，不要从目录里挑一个来点缀。

## 错误、重复与时间

| 模式 | 采用 | 放弃 |
| --- | --- | --- |
| 类型化结果 | 失败是业务的正常返回，调用方必须分支 | 用空值或魔法数表示冲突 |
| 幂等键 | 入口可能重放同一次请求 | 把「再查一次是否存在」当成幂等，却没有稳定的请求标识 |
| 乐观版本 | 冲突少，失败可以重试一次或返回冲突 | 版本打在错误的行上，守不住真正的不变量 |
| 条件更新 | 用「版本等于读到的值」让第二个写入者失败 | 先查再写且中间没有条件 |
| 悲观行锁 | 乐观重试会把延迟预算用完，且锁不跨外部调用 | 锁住整张表 |
| 发件箱 | 架构要求写入和消息同成同败 | 写库成功后再直接调用另一个模块的网络接口 |
| 重试一次 | 只有版本冲突这种可恢复失败 | 对非法输入和状态错误重试 |

## 数据映射

| 模式 | 采用 | 放弃 |
| --- | --- | --- |
| 单事务身份映射 | 同一次命令里同一标识不能变成两个对象 | 命令之间缓存领域对象 |
| 数据映射器 | 领域对象和表结构会分开变 | 两者本来一一对应，映射器只有样板 |
| 区间或重叠查询 | 不变量是时间段或范围重叠，需要能在事务内按范围读到已提交的行 | 用一个等值唯一键假装能表示重叠 |

发件箱的投递器不是领域模型的一部分。它只读已提交的发件箱行，成功后标记已投递，失败留下次再读。投递器的失败不得回滚已经确认的业务写入。
