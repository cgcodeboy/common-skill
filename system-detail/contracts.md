# 契约

每个本单元提供的命令、查询，以及它发出或消费的每条消息，都用下面的字段写。查询没有副作用。命令才有事务。消息写明至少一次还是仅一次，以及消费端如何识别重复。

| 字段 | 要求 |
| --- | --- |
| 名称 | 领域动词，不用 CreateOrUpdateData |
| 调用方 | 哪一个已经存在的单元或入口。不写「用户」来代替界面背后的入口 |
| 前置 | 调用前必须已经为真的状态。不满足时返回哪一个错误 |
| 输入 | 字段、哪些必填、标识用什么 |
| 成功 | 返回给调用方的内容，以及提交了哪些写入 |
| 错误 | 至少区分：非法输入、状态不允许、冲突、依赖不可用。每种错误是否改动了持久化 |
| 幂等 | 重复键是什么。重复时返回第一次的成功或第一次的错误，且不第二次写入 |
| 副作用 | 发出什么消息，是否与写入同一事务 |
| 超时与重试 | 调用方最多做几次；本单元是否自己重试版本冲突 |

错误用一种主模型：类型化结果，或带稳定错误码的失败。不要有的操作抛异常、有的返回空、有的用布尔值。异常若存在，只表示本单元没有处理的缺陷，不表示业务冲突。

幂等键由调用方传入，例如请求号。不要只用「看起来像同一条」的业务字段当幂等键，除非场景写明业务字段本身必须唯一。

依赖别的单元时，同样按这些字段写本单元怎么用它：超时、失败时本事务是否还没开始、能否安全重试。在事务提交之后才投递的消息，要写谁负责重投，以及最老未投递年龄如何对应架构里的可见性度量。

契约里不出现界面控件、页面步骤和文案。那些属于 `/system-interaction`。
