# 数据库设计说明书

本单元拥有持久化数据时，必须另交一份 `docs/数据库设计说明书.md`。已有同名文件就增补本次的表，不改其他单元的表，不另写 `数据模型.md` 或 `数据库设计-<单元>.md`。

章节按 GB/T 8567-1988 第 13 章。标题使用下面的名字。概念结构就是数据模型。逻辑结构、物理结构和数据字典才是可以拿去建库的数据库设计。聊天里的表说明、详细设计里的「存储分配」一句话，都不能代替这份文件。

概要设计第 11.5 节只保留数据集合的名称、所有者和集合之间的关系。字段、键、索引写在这里，不回写去扩写概要设计。

1. 引言：编写目的（读者是建库和写该程序的人）、背景（库的名称、使用它的系统）、定义、参考资料。参考资料包含概要设计说明书和框架设计。
2. 外部设计
   - 标识符和状态：库的代码或名称。试验库、临时库要写明有效期。
   - 使用它的程序：本次程序的名称和标识符。不把无关程序编进来。
   - 约定：表、列、版本号怎么命名。
   - 专门指导：写入这些表的数据格式。操作步骤若很长，指向详细设计里对应程序的流程逻辑。
   - 支持软件：架构已经选定的数据库管理系统，写明名称和数据模型类型。这里不更换数据库产品。
3. 结构设计
   - 概念结构设计：本单元拥有的实体、属性、关系。每个属性写标识符、定义、类型、值域、是否可空。每条不变量写在它守住的那个关系上。这是数据模型。没有这节，逻辑结构就不许开始写。
   - 逻辑结构设计：由概念结构分解或合并后的表。每张表写列名、类型、是否可空、主键、外键、唯一约束，以及表和表怎么关联。版本或幂等若存在，必须是某一列，并写明为什么是这一列、否决了哪一列。
   - 物理结构设计：每条索引对应程序里的哪一次查找或约束。写明访问方式。锁或缓冲若会影响不变量是否成立，写在这里。标准里的外存设备和数据块划分，架构没给定就写不适用和原因，不编造磁盘型号。
4. 运用设计
   - 数据字典设计：本次表和列的标识符、中文名、同义名、类型、值域。
   - 安全保密设计：谁能读、谁能写，依据概要设计里的权限。没有区分就写不适用和原因。

本单元不拥有数据库对象时，不新建这份文件。在详细设计的存储分配写明不适用。已有文件时不要为了本次去改别人的表。

不在这份说明书里更换数据所有者，也不新增架构没有的第二个真相。做不到时退回概要设计或框架设计。
