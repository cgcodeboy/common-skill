# 使用

先按 [interaction-install.md](interaction-install.md) 装到个人技能目录，并新开对话。

## 怎样开口

显式调用：

```text
/system-interaction
调度要在早高峰处理月台冲突，冲突要一眼看见。先做交互和一版能点的原型。
```

也可以不打斜杠，直接说要做系统交互、交互设计、界面原型、信息架构，或要体验已经做出来的界面再改。描述里带这些事，对话会选用本技能。

本对话一旦开始做交互，后面的「改成向导」「冲突看不清」不用再打斜杠。

## 会得到什么

一版接近成品的 UI/UX 稿，在产品仓库的 `prototypes/<短名>/index.html`。浏览器直接打开。数据和逻辑是假的。画之前会在浏览器里打开至少两个同类任务的工作界面，按看到的版式和用色来画。营销页、概念稿和凭记忆想起的界面不算。稿面要美观、大气、简洁：主工作区占住画面，颜色少，没有渐变卡片。

- 能看清成品里这一屏的布局、组件和状态，不是线框或灰盒
- 主任务能点完：选中、修改、冲突、失败会改变画面
- 假数据够密，能看出真实工作量

只有 Markdown、线框或「接下来可以做原型」，不算用完这个技能。

## 怎样提修改

指出任务变了，或指出走界面时停住的地方。例如「拒绝不能撤销」会改确认方式；「改成一步步向导」会先被拿去对照原来的步数标准。若向导让原标准失败，会先给一个不拆主界面的改法。你再明确坚持，才会换掉那一轴。

## 不负责什么

服务怎么拆、数据库谁拥有、要不要微服务，用 `/system-architecture`。两个技能可以先后用：架构定边界，交互定人在那个边界上怎么完成任务。交互交付里不要重开架构决策。

## 技能里的例子

`dock-desk-example.md` 是给执行这个技能的对话看的校准件，不是给你抄的成品界面。换一个业务，任务和否决都要重做。
