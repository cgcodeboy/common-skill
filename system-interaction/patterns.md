# 交互模式

三轴先选定，再扫描下面四族。不要在族里重新投票选出第二个主模型。

每一族在交付里只有两行以内：没有这类问题；或者选了谁、放弃了同族的谁、依据哪条任务。同族没被点名的模式不用逐个写否决。

一个模式若已经改变了任务的对象（人不再觉得自己在改预约，而觉得自己在填向导），它就不再是控件，回到三轴重选。

## 呈现轴

人第一眼如何看见对象。只留一个。

| 选择 | 留下 | 否决 |
| --- | --- | --- |
| 表格 | 要比较字段、筛选、对多条做同一动作 | 决定取决于时间重叠、空间关系或先后因果，表格把关系压扁了 |
| 主从列表 | 反复从一批里打开一条来判断 | 一屏必须同时看见很多条的细节才能比较 |
| 看板 | 对象的工作阶段就是人要推进的东西 | 阶段很少，或同一阶段里要比较大量字段 |
| 日历或时间格 | 冲突就是时间重叠，资源是列 | 对象没有时间窗 |
| 甘特或排程条 | 既要看时间重叠，又要看工期长短 | 只是挑一个日期，不看持续时间 |
| 时间线 | 要沿发生顺序追一条因果 | 人要改的是当前状态，不是过程 |
| 画布 | 对象之间的位置或连线就是工作对象 | 只是一张需要编辑的表 |
| 平面图 | 决定依赖物理位置，例如月台、货位、座位 | 位置不参与判断 |
| 树 | 层级本身是对象，人要在父子之间移动 | 层级只有两层，树变成多点的菜单 |
| 总览再下钻 | 先判断整体是否异常，再进入一个点 | 人的工作是逐条录入，没有「整体」可看 |
| 文档流 | 内容本身被阅读和轻量改写 | 要高密度比较数值 |
| 收件箱 | 工作是把涌入的事项清空，处理完就离开视线 | 事项要留在原地长期比较 |

## 编辑轴

选中之后如何改。只留一个主方式。

| 选择 | 留下 | 否决 |
| --- | --- | --- |
| 检查器 | 在不离开列表或日历的情况下改一条的若干字段 | 字段多到检查器变成第二张页面，列表失去上下文 |
| 就地编辑 | 改的就是格子里那一个值，改完还要继续扫下一格 | 一个值的修改会牵动校验、权限和相邻对象 |
| 整页 | 这条对象本身就是一项长时间工作 | 人每小时要在几十条之间跳 |
| 模态对话框 | 必须先做完或明确放弃，才能回到原处，且字段很少 | 人要对照后面的列表才能填 |
| 抽屉 | 需要一组字段，但仍要看见被挡住的一部分上下文 | 抽屉里又打开抽屉 |
| 分步向导 | 顺序不能乱，后面的步骤依赖前面的校验，人很少走回头路 | 专家要在多项之间反复改同一个字段 |
| 直接操纵 | 拖动、拉伸本身就是改时间或改位置，结果一眼能核对 | 精度要求高，拖动会产生大量误操作且难撤销 |
| 批量条 | 主任务是对当前筛选结果施加同一个动作 | 每条的判断依据都不同 |

## 寻找轴

如何到达那一条。可以有一个主方式和一个辅助，辅助必须服务于主任务，例如日历靠筛选定仓，命令面板只用于已知预约号。

| 选择 | 留下 | 否决 |
| --- | --- | --- |
| 筛选和保存视图 | 人每次用同一组条件缩小一批对象 | 条件每次都不同，保存视图没人会用 |
| 搜索 | 人记得名字、单号或供应商的一部分 | 人只认得样子或时间，不记得名字 |
| 命令面板 | 专家知道自己要去的对象类型，想少走路 | 第一次来的人要靠它认路 |
| 面包屑和层级 | 对象天然有父子，人会逐层下去再上来 | 层级是为了模仿组织架构，任务并不沿着它走 |
| 最近与收藏 | 同一小撮对象被反复打开 | 工作是处理新涌入的东西 |
| 分面 | 几个维度要同时收窄，例如仓、时段、状态 | 维度只有一个，分面是多余的控制面板 |

## 反馈、风险、空与失败

呈现轴已经定时，这一族只补主任务会碰到的状态。不会碰到的写不适用。

| 模式 | 采用 | 放弃 |
| --- | --- | --- |
| 乐观更新 | 失败很少，界面可以先呈现结果再回滚 | 失败常见，人会基于假结果做下一个决定 |
| 骨架或占位 | 等待超过大约一秒，且布局稳定 | 等待短到闪一下骨架更吵 |
| 内联校验 | 错误能指向具体字段 | 错误属于整次提交的业务规则，字段旁写不下 |
| 撤销条 | 动作可逆，撤销窗口用秒数写明 | 动作不可逆，撤销条会让人以为还能救 |
| 二次确认 | 不可逆且代价高，人可能点错 | 高频且可逆，确认框会训练人无脑点下去 |
| 键入名称确认 | 破坏的是难以恢复的整批数据 | 只是单条可逆编辑 |
| 冲突对比 | 别人或另一次提交改了同一条，人必须看见两边 | 后写覆盖不会造成业务损失 |
| 空状态 | 没有对象时仍要告诉人下一步是什么 | 空是因为筛选过严，却把空状态写成「去创建」 |
| 无权限 | 人需要知道为什么不能做 | 这个角色根本不该看见该入口；隐藏即可 |
| 部分失败 | 批量里有的成功有的失败，必须逐条给出结果 | 批量是一个事务，要么全成要么全败 |
| 保留上下文 | 保存、取消或冲突之后，筛选、滚动和选中还在 | 任务完成后这条就该从视线里消失 |

键盘：主任务若是专家每天重复多次，主路径上的打开、保存、撤销、下一条要有键位。偶尔使用的审批不必做命令面板。键位写进规格，并在原型里能触发。
